## Validation

The current reports are generated by scripts/check_release.py and
scripts/run_notebooks.py. CPU-only validation keeps CUDA skips explicit.
The CI workflow covers Linux/macOS/Windows, Python 3.10–3.14, minimum NumPy,
Torch CPU, real Jupyter execution, core-dependency advisories and installed
wheel/source-distribution checks. Consult GitHub Actions for its live result;
workflow files alone do not establish a passing run.

Fresh CUDA validation must run on an actual CUDA host. From this checkout, with
the intended CUDA-enabled PyTorch environment activated:

```bash
bash scripts/validate_cuda_release.sh
```

That command requires all 133 tests to pass with no skips and runs all seven
notebooks through Jupyter with GPU required. It does not replace the installed
PyTorch build. The audit host has no CUDA device and denies Jupyter kernel socket
creation, so its local standalone notebook results do not certify those checks.

## Index staging and stable release

The intended distribution name is nexqus-sdk and the import is nexqus.
TestPyPI staging requires a signed-in TestPyPI account or configured Trusted
Publisher for Inn0m1n4te030/NexQus-SDK, publish.yml, environment testpypi.
Production uses the separate pypi environment and publisher.

Use the manual publish workflow from the reviewed commit after the required
checks. Stage 1.0.0rc1 on TestPyPI, verify a clean index installation, and retain
the artifact hashes. Promote to 1.0.0 only after candidate GPU/Jupyter validation
and the review are complete. RELEASING.md contains the full sequence.

No uploaded index release is implied by this document; verify the index page and
the corresponding successful publishing workflow before announcing publication.
